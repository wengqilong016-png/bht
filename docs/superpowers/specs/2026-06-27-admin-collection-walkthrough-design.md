# 管理端逐字段收款核查 —— 设计规格说明书

📅 生成日期: 2026-06-27
🧑‍💻 状态: 已批准 (Approved)

本设计将管理端现有的 `ManualCollectionEntryPage`（快速补录）从单表单模式重构为**司机+日期维度的逐机器线性步进核查流程**。管理员选择一个司机和一个日期，系统自动列出该司机当天所有机器，对每台机器以 7 步逐字段推进，每步一个 [确定]，走完自动跳下一台。

---

## 1. 业务目标

* **审核提效**：管理员逐项走读审核司机已提交的日结数据，无需在密密麻麻的表单中翻找
* **代录友好**：管理员代替司机录入时，只需按顺序填关键字段，系统自动算分红/营业额
* **防遗漏**：系统自动排列当天所有机器，不会漏掉任何一台
* **每台独立提交**：第 7 步完成后立即提交该台机器，出错只影响当前机器，不丢前面已提交的数据

---

## 2. 入口与交互流程

### 2.1 入口

管理端 → 副导航 → **「采集录入」** → 显示新的逐字段核查页面（替换旧的 ManualCollectionEntryPage）

### 2.2 顶部选择栏

```
┌──────────────────────────────────────────────────────┐
│ 司机: [Rajabu ▼]   日期: [2026-06-01 ▼]   🔴 覆写  │
│                                                      │
│ 今日机器: 5 台  │  已完成: 2 台  │  进度 ████░░ 40%  │
└──────────────────────────────────────────────────────┘
```

* 选择司机后，自动加载当天该司机有交易记录的机器列表（从 `transactions` 表按 `driverId + date` 查询）
* 如果当天该司机没有任何记录，列表为空，显示「该司机今日无收款记录，将进入代录入模式」
* 覆写开关**默认开启**：允许读数低于上次、取消金额上限

### 2.3 7 步序列（每台机器）

```
┌──────────────────────────────────────────────┐
│ ← 上一步    Rajabu · Spot 12 M54    跳过此台 → │
│              机器 1 / 5                       │
├──────────────────────────────────────────────┤
│                                              │
│  步骤 1/7 · 今日分数                         │
│  ┌──────────────────────────────────────┐    │
│  │  上次读数: 83,900                     │    │
│  │  本次读数: [___84250___]              │    │
│  │  差值: +350                           │    │
│  └──────────────────────────────────────┘    │
│                         [确定 → 分红计算]     │
│                                              │
└──────────────────────────────────────────────┘
```

每步布局：
- 顶部：步骤序号 + 步骤名 + 机器名 + 进度
- 中间：当前步骤的输入/选择 + 自动计算结果
- 底部：一个大 [确定 → 下一步名] 按钮

### 2.4 7 步详细定义

| 步骤 | 显示内容 | 管理员操作 | 默认值来源 |
|---|---|---|---|
| ① 今日分数 | 上次读数(只读) + 本次读数(可编辑) + 自动差值 | 确认已填值或手动输入 | `tx.currentScore` 或空 |
| ② 分红计算 | 自动算出的分红金额 `diff × 200 × rate` | 确认或修改 | 自动计算 |
| ③ 营业额 | 自动算出的营收 `diff × 200` | 确认 | 自动计算 |
| ④ 留存/支付 | 二选一：留存(计入业主分红余额) / 支付(当场给业主) | 选择后确认 | `tx.isOwnerRetaining` |
| ⑤ 小费支出 | 金额输入框 | 输入或保持 0 | `tx.tip` 或 0 |
| ⑥ 其他支出 | 金额 + 支出分类下拉 | 输入或保持 0 | `tx.expenses` 或 0 |
| ⑦ 换币 | 金额输入框 | 输入或保持 0 | `tx.coinExchange` 或 0 |

第 ⑦ 步的 [确定] 按钮文案变为 **[提交并下一台 →]**，点击后调 `submitManualCollection` RPC 落库。

### 2.5 全部完成

最后一台机器提交后：

```
┌──────────────────────────────────┐
│         ✅ 全部完成               │
│                                  │
│  Rajabu · 6月1日                 │
│  已完成 5/5 台机器                │
│  总营业额: TZS 350,000            │
│                                  │
│       [返回选择司机]              │
└──────────────────────────────────┘
```

## 3. 技术设计

### 3.1 数据源

| 数据 | 来源 |
|---|---|
| 司机列表 | `useAppData().drivers`（现有） |
| 机器列表 | `useAppData().locations`（现有） |
| 当天交易 | `useAppData().transactions`，按 `driverId + date` 过滤 |
| 提交 | `useMutations().submitManualCollection`（现有） |

### 3.2 状态机

```typescript
type PageState = 
  | { step: 'selecting' }                          // 选择司机+日期
  | { step: 'walkthrough'; machineIndex: number; subStep: 1|2|3|4|5|6|7; draft: CollectionDraft }
  | { step: 'complete'; summary: {...} }           // 全部完成
```

### 3.3 机器列表构建逻辑

选择司机 + 日期后：
1. 从 `transactions` 查该司机当天的所有记录 → 得到已有数据的机器列表
2. 从 `locations` 查该司机绑定的所有机器（`assignedDriverId === driverId`）
3. 合并去重，按时序或名称排序
4. 如果某台机器在当天无交易记录 → 以空 draft 进入代录入模式

### 3.4 修改范围

| 文件 | 改动 |
|---|---|
| `admin/ManualCollectionEntryPage.tsx` | 完全重写为步进器模式 |
| `i18n/zh.ts` | 新增步骤标题等翻译 key |
| `i18n/sw.ts` | 对等新增斯瓦希里语（管理端用中文为主，保留 sw 兼容） |
| `__tests__/ManualCollectionWalkthrough.test.tsx` | 新增测试 |

**不碰**：司机端、FinanceSummary、QuickCollect、SettlementTab、supabase RPC。

### 3.5 安全约束

* 每步 [确定] 时做本地校验（非空、数字有效）
* 覆写模式默认开启，管理员可在顶部关闭
* 所有提交走现有 `submitManualCollection` RPC，保留审计日志
* 离线时不可用（和现在一致）

## 5. 测试覆盖

| 场景 | 断言 |
|---|---|
| 选择司机后加载机器列表 | 列表正确渲染，包含该司机当天所有机器 |
| 无交易记录的机器进入代录入 | 显示空输入框，管理员可手动填 |
| 7 步依序推进 | 每步显示正确字段，[确定] 后进入下一步 |
| 已提交机器自动跳过 | 提交完成的机器标记"已完成"，下次进入默认跳过或显示为灰色 |
| 最后一台提交后显示完成页 | 汇总显示总机器数、总营业额 |
